# Локальная проверка текстовых совпадений

Модуль проверяет только DOCX-работы, загруженные через раздел проверки
документов преподавателем. Каждая новая работа после форматной проверки
сравнивается с ранее проиндексированными работами **той же организации**.
Результат — поиск текстовых совпадений, а не автоматическое заключение о
плагиате.

## Что получает преподаватель

- процент совпавших слов в проверяемом тексте;
- число слов, исключённых из анализа;
- число доступных и реально просмотренных документов коллекции;
- список максимальных совпадающих фрагментов с подсветкой абзацев в
  предпросмотре;
- отдельную историю результатов для каждого перезапуска проверки.

Алгоритм первой версии — `local-exact-sequence-v1`: он находит непрерывные
точные последовательности слов. Порог по умолчанию — 8 слов. Совпавшие слова
в пределах абзаца учитываются один раз, поэтому несколько пересекающихся
фрагментов не завышают процент.

## Исключения и конфиденциальность

Из сравнения исключаются заголовки, таблицы, автоматически распознанная первая
страница, абзацы со стилем цитаты, цитаты в кавычках и раздел `Список
литературы`/`References` вместе с последующим списком источников.

Исходный DOCX никогда не отдаётся другому преподавателю. Имя источника,
абзац и отрывок источника видны только его владельцу либо если владелец отметил
«разрешить показывать сведения об источнике» при загрузке. Иначе интерфейс
показывает только факт ограниченного совпадения и отрывок проверяемой работы.

Отсутствие совпадений означает лишь отсутствие совпадений в доступной
организационной коллекции: это не проверка всего интернета и не оценка
перефразирования.

## Параметры и запуск

Настройки окружения:

| Переменная | Значение по умолчанию | Назначение |
| --- | ---: | --- |
| `LOCAL_PLAGIARISM_MIN_MATCH_WORDS` | `8` | Минимальная длина точного совпадения (не меньше 3). |
| `LOCAL_PLAGIARISM_MAX_MATCHES` | `300` | Максимум сохраняемых фрагментов результата. |
| `LOCAL_PLAGIARISM_MAX_CANDIDATE_DOCUMENTS` | `250` | Лимит документов коллекции за один запуск. |
| `LOCAL_PLAGIARISM_MAX_INDEXED_WORDS` | `100000` | Лимит нормализованных слов одной работы. |

Перед развертыванием примените миграцию:

```powershell
Set-Location backend
.\.venv\Scripts\alembic.exe upgrade head
```

Затем должен работать `document-check-worker`: он извлекает текст, создаёт
индекс новой работы и сохраняет результат рядом с обычной проверкой формата.

## Изоляция ошибок worker

Обработка разделена на два последовательно запускаемых дочерних процесса:

1. Чтение приватного оригинала, проверка размера и SHA-256, анализ оформления.
2. Извлечение текста, чтение коллекции и вычисление локальных совпадений.

Каждый этап ограничен `DOCUMENT_CHECK_WORKER_TIMEOUT_SECONDS` отдельно.
Родительский worker продлевает lease во время обоих этапов и останавливает
дочерний процесс при тайм-ауте, остановке worker или потере владения заданием.
Истёкший lease нельзя продлить; такое задание должен восстановить механизм
`recover_stale`. Старый worker не может записать результат или ошибку вместо
нового владельца.

Второй процесс использует отдельное соединение PostgreSQL с транзакцией
только для чтения. Он возвращает рассчитанный результат и не записывает
индекс, совпадения или статусы. Поэтому его принудительное завершение не
оставляет частично сохранённых совпадений.

Если второй этап завершился с ошибкой, завис или не смог запуститься, готовые
замечания по оформлению сохраняются, а локальное сравнение получает `FAILED`.
Запись индекса и совпадений защищена savepoint: ошибка этой записи откатывает
только локальный результат, после чего сохраняются ошибка сравнения и готовый
результат оформления. Оба исхода фиксируются одной транзакцией под блокировкой
задания; ожидание SQL-запросов и блокировок ограничено.

При недоступности самой базы зафиксировать результаты невозможно: остаётся
обычный механизм повторных попыток и восстановления lease. Изменение не
добавляет отдельную очередь и не требует новой миграции.

Регрессионные сценарии добавлены в `backend/unit_tests/test_local_plagiarism.py`
и `backend/app/tests/test_document_check_phase21.py`: тайм-аут и остановка обоих
этапов, потеря lease, ошибка сравнения, откат частичной записи, сохранение
замечаний оформления и успешное выполнение двух дочерних процессов.
В рамках этой доработки тесты не запускались по ограничению пользователя.
