# Проверка Phase 2.2: анализ готовых DOCX

Дата проверки: 8 сентября 2026 года.

Текущий teacher-only вход и результаты его повторной проверки описаны в
[`TEACHER_ONLY_DOCUMENT_CHECKS.md`](TEACHER_ONLY_DOCUMENT_CHECKS.md). Он заменяет
описанный ниже student-facing способ запуска, сохраняя анализатор Phase 2.2.

## Реализованное поведение

- После загрузки оригинального DOCX создается долговечное задание в PostgreSQL.
- Отдельный процесс `document-check-worker` забирает задания конкурентно через `FOR UPDATE SKIP LOCKED`, продлевает аренду, ограничивает время анализа и повторяет временные сбои не более заданного числа раз.
- Перед анализом worker повторно проверяет максимальный размер и SHA-256 оригинала. Файл передается анализатору через приватную временную копию и не изменяется.
- Анализатор читает OOXML с ограниченными XML-настройками и сохраняет только структурированные отклонения. Текст документа в результаты и журнал аудита не попадает.
- Результаты привязаны к точной версии профиля и неизменяемы после завершения задания. В текущем режиме их видит только преподаватель, загрузивший оригинал, внутри своей организации.
- Интерфейс показывает число отклонений, количество проверенных и пропущенных правил, признак усечения и постраничный список отклонений. Скачивание исходного DOCX сохранено без изменений.

## Поддерживаемые правила

| Тип правила | Что проверяется |
| --- | --- |
| `PAGE_FORMAT_MARGINS` | формат, ориентация и поля страницы |
| `FONTS_SIZES` | разрешенные шрифты и диапазон размера |
| `PARAGRAPH_SPACING_INDENTS` | интервалы и отступы абзацев |

Остальные типы правил сохраняют конфигурацию профиля, но в Phase 2.2 явно учитываются как пропущенные. Система не выставляет оценку, не исправляет документ и не добавляет аннотации в оригинал.

## API и хранение

- `POST /api/v1/document-checks/teacher/submissions` принимает от преподавателя DOCX, точную опубликованную версию профиля и необязательную подпись студента/работы. Аккаунт студента и назначение группе не требуются.
- `GET /api/v1/document-checks/teacher/submissions/{submission_id}/findings` возвращает преподавателю-владельцу результаты с пагинацией.
- Студенческие маршруты проверки по умолчанию отключены, скрыты из OpenAPI и возвращают `404`.
- Сводка задания содержит версию анализатора, общее число правил, числа выполненных и пропущенных правил, число сохраненных отклонений и признак усечения.
- Таблица `document_check_findings` хранит код, важность, структурное местоположение, ожидаемое и фактическое значение. Ограничения и триггеры PostgreSQL запрещают изменение результатов и завершенных заданий.
- События начала, завершения и окончательного сбоя задания записываются в аудит.

| Тесты интерфейса проверки документов | 19 тестов пройдено |

Две ошибки полного backend-набора относятся к существующему PDF-экспорту: в локальном окружении нет его нативных библиотек рендеринга. Оба теста Phase 2.2, запущенные после финального уточнения схемы API, прошли; функциональность DOCX этими двумя ошибками не затронута. Машиночитаемый отчет полного прогона сохранен в `outputs/phase22-validation/backend-full.xml`.

## Эксплуатационные границы

- Очередь проверки DOCX работает через PostgreSQL и не использует Redis-очередь PDF-экспорта.
- Тайм-аут анализа должен быть меньше срока аренды задания; это проверяется при запуске конфигурации.
- Число сохраняемых отклонений ограничено настройкой `DOCUMENT_CHECK_MAX_FINDINGS`; усечение явно отражается в сводке.
- После исчерпания попыток пользователю возвращаются стабильные безопасные коды ошибок без содержимого документа и внутренних трассировок.
