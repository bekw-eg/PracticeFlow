# Презентация результатов проверки группы

На странице **Группы проверки → БК 2405** преподаватель нажимает
**Сформировать презентацию отчёта о проверке**. Создаётся приватный черновик
со снимком всей группы, независимо от страницы и фильтра таблицы.
Нужна хотя бы одна завершённая преподавательская проверка с доступным
COMPLETED результатом закреплённого `completed_job_id`.

Редактор содержит заголовок, вступление, сохранённую сводку, выбор типов
нарушений, конкретных findings, индивидуальных замечаний и выводы.
Замечания и примеры по умолчанию не выбраны. **Сохранить черновик** сохраняет
текст и выбор; **Предпросмотр содержания** сначала сохраняет их и показывает
именно сохранённое содержание. Это не точная визуальная копия PowerPoint.
После **Сформировать и скачать PPTX** содержание закрепляется. Список
**Отчёты группы** позволяет открыть черновик или повторно скачать готовый файл.
Для нового состояния группы создаётся новый отчёт.

## Данные и безопасность

- Используются `ReviewGroup`, `TeacherDocumentReview` и существующий
  `ReviewGroupService.summary`. Десять findings в одной работе дают десять
  нарушений и одну затронутую работу. Незавершённые преподавательские проверки
  и новые технические recheck не входят в уже созданный снимок.
- Отдельная PostgreSQL REPEATABLE READ транзакция согласованно фиксирует
  название группы, дату, полную сводку, ID закреплённых запусков и варианты
  замечаний. PostgreSQL trigger запрещает изменение снимка, владельца и языка,
  а после генерации — изменение сформированного отчёта.
- Findings неизменяемы в существующей модели. Их постраничный выбор ограничен
  точными запусками снимка. При сохранении сервер проверяет tenant, владельца,
  группу и завершённую проверку каждой работы/finding и сохраняет безопасную
  проекцию выбранных примеров в содержание. Предпросмотр и PPTX используют её.
- Автоматические примеры содержат только тип, числовые координаты документа и
  разрешённые структурные значения. Нет имени студента, названия работы/файла,
  исходных текстовых фрагментов, идентификаторов работ или запусков в PPTX.
  Неизвестные произвольные значения, в том числе необычные имена шрифтов,
  исключаются и показываются как недоступные. Это не универсальное обезличивание:
  вступление, выводы и явно выбранные замечания преподаватель просматривает сам.
- Частичная проверка, недоступные закреплённые результаты, ограниченный список
  findings и невыполненные правила сохраняются как ограничения и показываются
  в редакторе, предпросмотре и презентации. Отсутствие сохранённых findings не
  означает выполнения всех требований. Оценки и выводы автоматически не создаются.
- Все операции требуют роль TEACHER, организацию и владельца группы. Чужие
  ID возвращают 404, неподходящая роль — 403. Действует `DOCUMENT_CHECK_ENABLED`.
  Ответы имеют `Cache-Control: private, no-store`. Объекты хранятся через
  существующий приватный `StorageService`; публичных/подписанных URL нет.

## Генерация и ограничения первой версии

Добавлена таблица `group_review_reports` и новая миграция `5d6e7f8091a2` после
`4c5d6e7f8091`. Применённые миграции не меняются. Черновики используют optimistic
revision; конфликт вкладок даёт 409 и сохраняет локальный текст в UI.
UUID `request_id` обеспечивает идемпотентное создание после сетевой ошибки.
Блокировка строки сериализует сохранение и генерацию; повтор генерации возвращает
тот же результат, повтор скачивания — те же байты.

Шаблон 16:9 хранится в backend, создан с Artifact Tool. Runtime формирует
стандартный OOXML средствами Python stdlib. Текст, таблицы и горизонтальные
диаграммы остаются редактируемыми; диаграммы имеют встроенную XLSX с данными.
Русский, казахский и английский язык фиксируется по текущему языку интерфейса
при создании отчёта. Текст преподавателя не переводится автоматически.
Титул, объём, ограничения, вступление, проблемы, подробная статистика,
выбранные примеры, явно выбранные замечания и выводы разбиваются на слайды.
Длинные строки переносятся; текст не уменьшается до нечитаемого размера.

Выбранные примеры и замечания ограничены 30 каждого вида, вступление — 10 000,
выводы — 20 000, заголовок — 500 символов; максимум 250 слайдов.
Если выбранные замечания делают презентацию слишком большой, экспорт даёт 422:
сократите текст или выбор, черновик остаётся доступным. Генерация выполняется
синхронным сервисом в threadpool FastAPI под существующими Redis fail-closed
лимитами частоты и параллельных экспортов и deadline `EXPORT_TIMEOUT_SECONDS`.
Для ограниченного шаблонного OOXML отдельная очередь/AI не требуются.
Файл создаётся атомарно через `save_new`; ошибки хранения дают 503 и позволяют
повторить запрос. Объект записывается один раз; скачивание не пересчитывает отчёт.

Отчёты не имеют автоматического TTL: они входят в резервное копирование БД
и приватного storage. Удаление исходного DOCX по retention workflow не удаляет
отчёт. Оператор должен учитывать их в общей политике tenant retention;
новый публичный API удаления/массовой очистки в этой версии не добавлен.
Copy-only миграция LocalStorage → S3 включает сформированные отчёты, сохраняет
ключи и проверяет совпадение байтов; сначала примените текущую схему БД.
Откат миграции удаляет таблицу отчётов и её trigger, поэтому предварительно
сохраните БД и связанные приватные файлы; существующие группы и проверки
не изменяются. Внешний офисный renderer и PowerPoint на сервере не нужны.

## API и запуск

Префикс: `/api/v1/document-checks/teacher/groups/{group_id}/reports`.

- `POST /` — `{request_id, locale}`; снимок и черновик.
- `GET /` — постраничный список; `GET /{id}` — сохранённый отчёт.
- `GET /{id}/findings` — кандидаты с пагинацией и необязательным `rule_type`.
- `PUT /{id}` — revision, текст, типы, finding IDs и явно выбранные замечания.
- `POST /{id}/export` — `{revision}`; сформировать приватный PPTX.
- `GET /{id}/download` — авторизованное скачивание готового файла.

Обновите код и зависимости (`pip install -r backend/requirements-dev.txt`,
`npm ci` в frontend), примените `alembic upgrade head` в backend.
Для локального полного стека используйте `docker compose up --build` из
[README](../README.md). Должны работать PostgreSQL, приватное storage и
Redis resource guard; document-check worker завершает анализ загруженных работ.
Отдельный сервис для PPTX или внешний AI не нужен.

## Проверки

`app/tests/test_group_review_reports.py` проверяет права tenant/владельца/ролей,
весь объём статистики, completed_job_id, снимок после переименования и recheck,
явный выбор замечаний, безопасность примеров, revision, повторное скачивание
и database guard. `unit_tests/test_group_report_pptx.py` проверяет четыре
сценария в трёх языках, геометрию, сохранность длинного текста и редактируемые
диаграммы со встроенными данными. Frontend тесты проверяют недоступность,
сохранение/предпросмотр, ошибки, идемпотентный повтор и язык.

На синтетических данных сформированы реальные PPTX: частичная группа (RU),
без нарушений (RU), много типов нарушений (KK), длинный текст (EN).
Все слайды импортированы и отрендерены Artifact Tool для визуальной проверки.
Проверка в нативном Microsoft PowerPoint не выполнялась. Синтетические
артефакты и журналы проверки в Git не включаются.
