# Рабочее место преподавателя: группы проверки

Преподаватель открывает **Группы проверки**, создаёт группу (например, «БК 2405»),
загружает DOCX с именем/обозначением студента, названием работы, типом
«Курсовая» или «Отчёт» и опубликованной версией профиля с исполняемыми правилами.
Аккаунты студентов, учебная специальность и назначение практики не требуются.

`ReviewGroup` — отдельная лёгкая сущность. Учебные `Group`, `TeacherGroup`,
`Report` и `ReportVersion` сохраняют прежнее назначение. Группа принадлежит
одной организации и одному преподавателю; даже другой преподаватель этой же
организации не получает к ней доступ. Для недоступных идентификаторов API
возвращает 404, для неподходящей роли — 403. Действует `DOCUMENT_CHECK_ENABLED`.

## Загрузка и список работ

Используется существующий `TeacherDocumentSubmissionService.upload`, DOCX
preflight, ограничения ресурсов, приватный `StorageService`, неизменяемый
оригинал и очередь `DocumentCheckJob`. Добавлены необязательные поля
`review_group_id`, `work_title`, `work_type` (`COURSEWORK`/`REPORT`). Если задана
группа, все три описательных поля, включая `student_label`, обязательны.
Составной внешний ключ не допускает привязку работы к чужому владельцу/tenant.
Привязка фиксируется при загрузке; перемещение существующих работ в этом этапе
не предусмотрено. Документы без группы продолжают работать.

Группа, название и тип входят в идентичность `Idempotency-Key`. Повтор с тем же
ключом и теми же данными возвращает исходную работу, с другими данными — 409.
Форма сохраняет ключ после неопределённого сетевого сбоя до изменения полей или
успеха. Опубликованные профили загружаются постранично целиком.

Таблица поддерживает серверную пагинацию и фильтр `pending`/`completed` по
проверке преподавателем. Автоматический статус и число нарушений относятся к
последнему запуску; незавершённый/неуспешный анализ отображается без числа
нарушений, а не как ноль. Архивирование в общей истории не убирает работу из
группы и её сводки. Удаление оригинала через существующий retention workflow
также не удаляет структурные результаты и подтверждённую проверку.

## Замечания и завершение

`TeacherDocumentReview` хранит замечания (до 10 000 символов), revision,
`completed_at`, `completed_by_teacher_id` и `completed_job_id`. Черновые
замечания можно сохранять до готовности анализа. Завершение атомарно сохраняет
текущие замечания и конкретный завершённый запуск, чьи замечания загружены и
показаны на странице просмотра. Подстановка запуска другой работы даёт 404;
QUEUED, PROCESSING и FAILED не допускаются (409).

Запросы используют optimistic revision (0 до первого сохранения); конфликт
вкладок даёт 409. UI сохраняет локальный текст при ошибке и позволяет загрузить
сохранённый вариант. Блокировка строки исходной работы сериализует параллельные
сохранения и завершения, а точный повтор запроса безопасен.

После завершения замечания и выбранный запуск фиксируются; повторное открытие
показывает дату и кнопку **Показать подтверждённый запуск**. Редактирования
завершённой проверки/возврата на доработку в этом этапе нет. PostgreSQL trigger
защищает завершённую запись от изменения/удаления и проверяет владельца и
готовность результата. Составной FK связывает review с точным запуском той же
работы и организации. Аудит записывает действие без текста замечаний.

## Сводка

Backend агрегирует всю группу, независимо от страницы и фильтра таблицы:

- `total_works`, `pending_works`, `reviewed_works` — счётчики работ;
- `included_works` — завершённые преподавательские проверки с доступным
  COMPLETED результатом закреплённого запуска;
- `violations[]` — тип правила `rule_type`, число сохранённых нарушений
  `violations_count`, число различных работ `works_count`;
- `truncated_works` — число включённых работ с ограниченным анализатором
  списком нарушений. UI явно предупреждает о неполноте счётчиков.

Десять нарушений одного типа в одной работе дают 10 нарушений и 1 работу.
Завершённые анализы без подтверждения преподавателем в сводку не входят.
Технический recheck создаёт новый запуск, но не меняет `completed_job_id`,
замечания, время и статистику подтверждённой проверки. Числа основаны на
сохранённых findings, включая исходную severity; это не академическая оценка.
PPTX, исправленные документы и студенческие пересдачи не реализуются здесь.

## API

Все пути ниже начинаются с `/api/v1/document-checks/teacher`.

| Метод и путь | Назначение |
| --- | --- |
| `GET /groups?offset=0&limit=25` | Свои группы, стандартные X-Total-Count/X-Has-More/X-Offset/X-Limit |
| `POST /groups` | Создание: `name`, необязательное `description` |
| `GET /groups/{id}` | Группа владельца |
| `PUT /groups/{id}` | Полная замена названия и описания |
| `GET /groups/{id}/works?review_status=pending&offset=0&limit=25` | Работы, необязательный фильтр pending/completed |
| `GET /groups/{id}/summary` | Сводка всей группы |
| `POST /submissions` | Существующий multipart upload + новые поля группы/работы |
| `PUT /submissions/{id}/review` | Черновые замечания: `revision`, `remarks` |
| `POST /submissions/{id}/review/complete` | Завершение: `revision`, `remarks`, `job_id` |

DTO документа расширен полями группы/работы и `teacher_review`; прежние
маршруты оригинала, preview, findings, runs и recheck проверяют права владельца
документа. Новые маршруты групп и review отправляют `Cache-Control: private, no-store`.

## Запуск и проверка

1. Применить новую миграцию `4c5d6e7f8091`: из `backend` выполнить
   `python -m alembic upgrade head` с настроенным `DATABASE_URL`.
2. Перезапустить backend и существующий `document-check-worker`, собрать
   frontend (`npm run build`). Новых сервисов/переменных окружения не требуется.
3. Войти преподавателем при включённом `DOCUMENT_CHECK_ENABLED`, опубликовать
   профиль с поддерживаемыми правилами и открыть `/review-groups`.

Целевые регрессии: `backend/app/tests/test_review_groups.py` (на выделенной
PostgreSQL базе с именем `*_test`) и
`frontend/src/features/documentChecks/ReviewGroupsPage.test.tsx`, а также
существующие document-check tests. Общие команды CI описаны в
[README](../README.md).

  и `npm run lint` прошли. Vite предупреждает о размере основного JS chunk
  больше 500 kB; сборка успешна.

  Устаревшие ожидания OpenAPI и fixture production-конфигурации исправлены;
  повторный целевой прогон DOCX, групп, конфигурации и unit tests дал

  миграции, повторное применение и `alembic check` прошли без schema drift.
